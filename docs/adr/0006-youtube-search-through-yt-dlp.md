# Search YouTube through yt-dlp instead of the YouTube Data API

The KeyStack kiosk runs full-screen without tabs or an address bar, and YouTube pages refuse to load in iframes, so listeners need a way to find a Source Video without leaving the app. We search through the yt-dlp binary the importer already ships (`ytsearch10:` with `--flat-playlist`) rather than the YouTube Data API, because it needs no API key, Google project, or daily quota (the Data API allows roughly 100 searches per day on the default quota), and it keeps every YouTube dependency in one pinned tool. We accept that search can break when YouTube changes its site until yt-dlp is updated, which is already true of inspect and download, and that each search starts a Python process on the Pi 2. The endpoint is public like the rest of the importer (ADR 0003) and deliberately has no cache, concurrency limit, or query length limit; only a 30-second process timeout bounds a hung search. Revisit this if public search load measurably hurts streaming or imports on the Pi 2.
